- **A18 — Страницы банков и три рейтинга.** Каталог `/banks` (лидер объективного рейтинга в чёрной карточке, поиск по имени/коду/алиасу, сортировка: рейтинг, народный, ставка, алфавит; карточка банка с ячейками «ставка до · рейтинг · народный») и страница банка `/banks/{slug}` (о банке, лучшая ставка, три гейджа рейтингов с местом и ▲▼, все вклады банка, разбор объективного рейтинга по критериям, вывод редакции с плюсами/минусами, отзывы с распределением 5…1, форма отзыва, справка «О банке»). ## 2026-11-26 · Первый деплой на bank.tsoy.in

- **A19 — `deploy.sh` под BrainyCP с chroot.** Проект впервые развёрнут на сервере (bank.tsoy.in, `/home/tsoy/sites/banqofbank`; заглушка панели — в `/home/tsoy/banqofbank-placeholder-backup`). Выяснилось: PHP-FPM сайта работает в chroot `/home/tsoy` (сайт видит пути как `/sites/...`), поэтому `config:cache`/`view:cache` из консоли записали бы пути, которых сайт не найдёт. Теперь `deploy.sh` по умолчанию только очищает кеши (`optimize:clear`), кеширование включается `ARTISAN_CACHE=1` на серверах без chroot. PHP ищется сам (`php` в PATH, `/usr/bin/php83/bin/php`, `/usr/bin/php84/bin/php`), composer запускается через тот же PHP. В мастере установки хост БД — `127.0.0.1` (в chroot нет сокета MySQL). Корень сайта, версия PHP и SSL меняются только в панели BrainyCP: она перезаписывает ручные правки конфигов.

- **A20 — MySQL на BrainyCP: ключи и движок.** Мастер установки упал на `password_reset_tokens`: «Specified key was too long; max key length is 1000 bytes» — MySQL сервера по умолчанию создаёт таблицы в MyISAM. Теперь соединения mysql/mariadb всегда создают таблицы в InnoDB (`DB_ENGINE`, по умолчанию `InnoDB`), а `Schema::defaultStringLength(191)` держит индексы по строкам в пределах лимита даже на старых серверах.

## 2026-11-27 · Мультистрановость, обмен данными, админка

Запрос пользователя: проект не привязывать к Казахстану (это одна из стран), импорт/экспорт — универсальный («чтобы Claude собрал данные и залил»), админка — мощная.

- **A21 — Страна как сущность.** Таблица `countries` (ISO-код, slug, падежи названия, флаг, валюта и её знак, валюты вкладов, регулятор, центробанк, система гарантирования вкладов с лимитами по типам, meta). Миграция создаёт Казахстан (АРРФР, НБРК, КФГД с лимитами 20/10/10/5 млн ₸) и привязывает к нему все банки. `banks.country_id`; код банка уникален внутри страны; `is_kdif_member` → `deposit_insured` (участие в системе гарантирования своей страны). Текущая страна витрины — `App\Support\CurrentCountry` + middleware `ResolveCountry`: `?country=uz` → cookie на год → настройка `country.default` → первая. Каталог вкладов, банки, рейтинги, главная и бегущая строка показывают банки текущей страны; страница банка/вклада переключается на страну банка. Все «КФГД/АРРФР/НБРК/Казахстана/₸» в шаблонах берутся из страны (`country()`, `currency_symbol()`), лимиты гарантии — `Country::guaranteeLimit()` вместо `config('banq.kdif_limits')`. Переключатель стран в ленте (появляется, когда стран больше одной). Будущие разделы (карты, кредиты) получают страну так же — через `bank_id`.
- **A22 — Универсальный обмен данными.** `App\Services\Exchange`: сущности (`countries`, `banks`, `deposit_products`, `deposit_rates`) с полями, типами и естественными ключами (страна — ISO, банк — страна + код/имя/алиас, вклад — slug или банк + название, ставка — вклад + валюта + срок + порог суммы); форматы JSON (пакет, `{entity, rows}`, массив, JSON Lines), CSV (разделитель угадывается, русские заголовки, `_entity`), XLSX (лист = сущность). Вложенность: банк в стране, вклад в банке, ставки во вкладе. Повторная заливка ничего не дублирует; ставка — по правилу 5: новая закрывает старую, исторические записи (`valid_to`) добавляются как есть. Dry-run — тот же прогон в транзакции с откатом: честный предпросмотр с диффом «было → стало». Ошибка строки не валит импорт. История — `imports` (+ format, source admin/cli/api, mode, rows_failed, stats). Экспорт в тех же форматах, roundtrip «выгрузил → залил» = без изменений (тест). CLI: `banq:import`, `banq:export`, `banq:schema`. Русские сообщения валидации — `lang/ru/validation.php`. Старый импорт матрицы Excel остался отдельным пунктом и теперь учитывает страну.
- **A23 — API с токенами.** `/api/v1`: `schema`, `export`, `{entity}`, `import` (JSON-тело, файл или CSV; `dry_run`, `mode`, `country`, `entity`), `imports`. Токены `api_tokens` (в базе только sha256, права read/write, срок, последний IP) — выпуск в админке или `banq:token`. Описание — `docs/API.md`.
- **A24 — Админка на движке ресурсов.** `App\Admin\Resource` + `ResourceRegistry` + один `Admin\ResourceController`: список с поиском, фильтрами, сортировкой по колонкам, пагинацией (25–200), выбором строк и «всё по фильтру», массовыми действиями, экспортом выбранного (JSON/CSV/XLSX); форма по группам-карточкам, JSON-поля с точкой (`deposit_guarantee.limits.term`). Ресурсы: страны, банки (алиасы, реквизиты, финансы, массовая смена статуса), вклады (на странице правки — действующие ставки, история и «новая ставка», которая закрывает старую через движок обмена), ставки (только добавление/закрытие/удаление ошибочных), пользователи (только admin, себя не разжаловать). Глобальный поиск ⌘K, меню по разделам, мобильное меню. Обзор: счётчики-ссылки, страны, «что заполнить» (банки без вкладов, вклады без ставок, ставки старше 60 дней…). «Обмен данными»: файл или вставка → проверка → применить, экспорт, формат и шаблоны, история; «Токены API». Закрывает A15.

## 2026-11-27 · Три способа загрузки данных

Запрос: для депозитов, карт, пакетов и остальных продуктов — три пути: 1) файлы (JSON, XML и другие форматы); 2) полноценный API для ИИ-агентов — собирать и выгружать; 3) удобный ручной ввод в админке — таблица «как Excel» с горячими клавишами и вставкой диапазонов Ctrl+C / Ctrl+V. - **A39 — Каналы обмена данными.**

Удаления выполняются после записи, от детей к родителям, и только с `ImportOptions::allowDelete` (табличный редактор, API с правом `delete`, `banq:import --allow-delete`); иначе — ошибка строки. «Удалить» ставку = закрыть (`valid_to` = сегодня), история не теряется (правило 5); закрытую ставку по `_id` можно поправить на месте (опечатка в истории), у действующей смена срока/валюты/порога закрывает её и добавляет новую. Страну с банками удалить нельзя — понятная ошибка. В отчёте новое действие `deleted`. Экспорт умеет `_id` (`withIds`) и общий фильтр `updated_since`; `DataExchange::page()` — постранично.
  - **Файлы.** Новые форматы чтения и записи: **XML** (`<banq><banks><row>…`; понимает чужие выгрузки — любой корень, `<banks><bank code="…">`, атрибуты, `<rates><rate>`; DOCTYPE отклоняется — защита от XXE), **YAML** (`symfony/yaml`, даты не превращаются в числа), **NDJSON** (по объекту на строку с `_entity`), **TSV** (как Excel кладёт ячейки в буфер). Формат угадывается по содержимому. Исправлено: разбор JSON Lines резал кириллицу (`\R` без `/u`). Экспорт → импорт во всех 7 форматах ничего не меняет (тесты вкладов и карт).

Новое право токена `delete` (`banq:token --delete`). Заголовок `Idempotency-Key` — повтор запроса возвращает сохранённый отчёт (24 ч, заголовок `Idempotent-Replayed`), тот же ключ с другим телом — 409. В админке («Формат и API») — блок «Для ИИ-агентов» с инструкцией для промпта.
  - **Табличный редактор** `/admin/exchange/grid/{entity}` (меню «Обмен → Таблица», `Admin\GridController`, `resources/js/sheet.js`). Любая сущность реестра.
